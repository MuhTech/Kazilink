# KaziLink Tanzania — Incident Response Plan & Protocol

## 1. Incident Severity Classification Matrix

|   Level   | Severity     | Examples                                                                    |  Response SLA  | Command Lead            |
| :-------: | :----------- | :-------------------------------------------------------------------------- | :------------: | :---------------------- |
| **SEV-1** | **Critical** | Database breach, unauthorized admin role escalation, widespread downtime    | **< 15 Mins**  | Lead Security Architect |
| **SEV-2** | **High**     | AI endpoint failure, rate limiter bypass, credential stuffing spike         |  **< 1 Hour**  | DevSecOps Engineer      |
| **SEV-3** | **Medium**   | Single user account lockout issue, localized search performance degradation | **< 4 Hours**  | Support / Admin         |
| **SEV-4** | **Low**      | Minor UI security header cosmetic warning, non-critical logging delay       | **< 24 Hours** | Lead Developer          |

## 2. Incident Response Workflow

```
 +------------------+     +-------------------+     +--------------------+
 | 1. Detection     | --> | 2. Containment    | --> | 3. Eradication     |
 | (Alerts/Audit)   |     | (Lockout/Freeze)  |     | (Patching/Revoke)  |
 +------------------+     +-------------------+     +--------------------+
                                                             |
                                                             v
 +------------------+                               +--------------------+
 | 5. Post-Mortem   | <---------------------------- | 4. Recovery        |
 | (Documentation)  |                               | (Restore/Verify)   |
 +------------------+                               +--------------------+
```

### Phase 1: Detection & Identification

- Security alerts generated by `security_alerts` or `audit_logs` triggers.
- Failed authentication threshold breach detected by `rateLimiter`.

### Phase 2: Containment

- Revoke suspicious user session tokens via global sign-out (`supabase.auth.signOut({ scope: 'global' })`).
- Temporarily lock affected user/employer accounts.
- Apply temporary IP rate limit block in `rate-limiter.ts`.

### Phase 3: Eradication

- Identify root cause (e.g. leaked API key, malformed input payload).
- Rotate compromised API keys (Gemini API key, Supabase service keys).
- Deploy targeted code patch and run unit test suite (`bun run test`).

### Phase 4: Recovery

- Re-enable locked accounts after password reset / identity verification.
- Verify normal operation on Admin Security Dashboard (`/admin/security`).

### Phase 5: Post-Mortem

- Document timeline, impact, root cause, and preventative action items in `/docs/incidents/`.
